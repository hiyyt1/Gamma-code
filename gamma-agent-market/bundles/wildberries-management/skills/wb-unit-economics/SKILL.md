# wb-unit-economics

Для всех расчётов используй gamma-wb_analyse; Python stdlib модуль scripts/analytics.py выполняется сервером без сети. Отдельный запуск Bash не требуется. Полная схема: [references/input.md](references/input.md). Числа не рассчитывай в голове и не дописывай отсутствующие расходы нулями.
При прибыли получи детализацию finance или финансовую выгрузку, затем себестоимость CSV/XLSX. Если себестоимости нет, выполни доступный анализ выручки/затрат и задай один деловой вопрос с шаблоном: nmID или vendorCode, cost в RUB, период действия. После ответа продолжи задачу.
Различай продажу, возврат, заказ, выплату. Для продажи revenue — фактически реализованная выручка до отдельно указанных расходов, не сумма заказа и не выплата. Не вычитай комиссию повторно из ppvzForPay. Возврат задавай положительными суммами kind=return; возврат себестоимости только resalable=true.
Не делай нечёткое сопоставление артикулов по названию. Сохраняй ведущие нули barcode/vendorCode. Неоднозначные соответствия и разные цены себестоимости требуют исправления исходника или разделения периодов.
profit_known_costs — результат только после указанных расходов. При missing_cost=true прибыль null. missing_expenses выводи в отчёте; валовая маржа после COGS не равна операционной, неполная операционная не равна чистой прибыли. Для операционной используй только совместимый набор расходов. Налоги и стоимость капитала не предполагаются.
Сохрани ссылки на analysis.json, products.csv, products.xlsx, report.md. XLSX формулы не исполняются: попроси выгрузку значений, если формулы обнаружены. Для проверки оборачиваемости используй средний запас за период; без него не называй отношение к конечному остатку оборачиваемостью.
