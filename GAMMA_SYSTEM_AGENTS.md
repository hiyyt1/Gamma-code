# Системные агенты Gamma

Реализованы нативные primary agents `gamma` и `gamma-guide`. Они исполняются существующими OpenCode tools, permissions, провайдерами и сессиями. Отдельного runner, чата или tool loop нет. Существующие `build`, `plan`, служебные агенты, специализированные профили и native TaskTool сохранены.

## Архитектура и выбор агента

Общие промпты, встроенные ресурсы и карточки находятся в `packages/core/src/gamma/system.ts`. V1 регистрирует агентов в `packages/opencode/src/agent/agent.ts`, V2 — через штатный `packages/core/src/plugin/agent.ts`.

Без явно заданного агента или специализированной привязки используется `gamma`. Явная настройка `default_agent` продолжает действовать для совместимости. Gamma получает те же нативные возможности и ограничения, что `build`: разрешения пользователя и проекта, подтверждения опасных операций, tools, доступные skills/MCP и делегирование. Обязательных сторонних skills нет. Выход из `plan` выбирает стандартного исполнителя, по умолчанию Gamma.

Agent Market продолжает использовать существующую V1 интеграцию. Привязка специализированного профиля имеет приоритет для рабочего проекта. Выбор Gamma в Market снимает специализированный профиль через тот же атомарный механизм: подтверждение замены, проверка версии, запрет смены во время выполнения, идемпотентный requestId. В базе сохраняется служебная запись `gamma`, а публичный selection возвращает `agentId: null` с новой версией. Это сохраняет защиту от устаревших запросов. Файлы, предыдущие сессии и история не удаляются. Устаревшее имя market-агента в старой сессии после возврата разрешается в стандартного агента.

Список агентов в UI обновляется после применения профиля. Явно выбранный специалист не заменяется Gamma при создании чата. Сохранённый `Session.Info.agent` учитывается после перезагрузки.

## Промпты

`gammaPrompt` требует понять конечную цель, исследовать проект, действовать при достаточных сведениях, уточнять критические пробелы, планировать сложную работу, применять инструменты и проверять результат. Он запрещает выдумывать результаты, переписывать несвязанный код и терять пользовательские данные. Штатные permissions не обходятся.

`guidePrompt` ограничивает роль продуктовой помощью: сначала соответствующий встроенный skill, затем актуальный каталог через `gamma_help`, если нужен. Непроверенные возможности нельзя выдавать за реализованные. При запросе разработки Guide предлагает Gamma/специалиста и помогает сформулировать задачу. Ограничения обеспечиваются runtime permissions, а не только текстом промпта.

## Пять навыков Guide

Каждая папка в `packages/core/src/gamma/skills` содержит проверяемый `SKILL.md` и `product.md` с привязкой к текущему коду:

- `gamma-getting-started`: первый чат, интерфейс, необходимая настройка модели.
- `gamma-projects`: проекты, сессии, история, загрузка и предпросмотр файлов.
- `gamma-agents`: каталог, выбор профиля, команды, возврат к Gamma.
- `gamma-tools`: tools, permissions, skills, MCP и ограничения Guide.
- `gamma-troubleshooting`: ошибки модели, доступа, занятости проекта, версии привязки и внешних зависимостей.

Ресурсы включаются в поставку и возвращаются стандартным skill tool без чтения пользовательских файлов. Пять имён зарезервированы для доверенных знаний Guide; локальный файл с таким же именем не подменяет его справку. Установка из GitHub не требуется.

### Актуализация знаний

`packages/core/src/gamma/knowledge-sources.json` фиксирует SHA256 16 исходных файлов, на которых основана справка. Из `packages/opencode`:

```sh
bun run script/gamma-guide-audit.ts
```

При несовпадении нужно проверить изменившийся интерфейс/API, обновить соответствующие SKILL.md/product.md, выполнить тесты и только затем записать новую точку проверки:

```sh
bun run script/gamma-guide-audit.ts --refresh
```

Проверку следует включать в CI при изменении продукта. Хеши обнаруживают изменение источников, но не доказывают смысловую корректность текста. Новые функции должны добавляться в ресурсы вместе со ссылками на их исходники.

## Permissions и безопасная диагностика

Guide имеет deny-by-default. Разрешены только `question`, `gamma_help` и загрузка пяти перечисленных skills. Запрещены произвольные read/glob/grep, write/edit, bash, сетевые tools, MCP и TaskTool. Общее разрешение `* = allow` не расширяет границы Guide. В V1 Help-сессия дополнительно сохраняет ограничивающие session permissions и фиксирует роль Guide; попытка передать `agent: build` при продолжении такой сессии не превращает её в coding-agent. Проектные AGENTS.md не подмешиваются в его системные инструкции.

`gamma_help` зарегистрирован в нативных V1 ToolRegistry и V2 Tools. Он возвращает безопасные сведения о возможностях и текущий каталог через AgentMarketService: идентификаторы, описания, задачи, доступность и ограничения. Ключи, конфигурация провайдеров, приватные логи и пользовательские файлы не возвращаются. Каталог не является health-check всех внешних сервисов. Guide не проводит произвольную диагностику shell-командами.

## Помощь, проекты и UI

Раздел «Помощь» и карточка Gamma Guide вызывают авторизованный `POST /product/help/session`. Сервер создаёт обычную Session с агентом `gamma-guide` в отдельной директории `<Global.Path.data>/gamma-help`. Рабочая project binding не изменяется. UI открывает существующую страницу сессии; второй чат не создаётся. В Help-сессии файловая панель скрыта, поскольку Guide не работает с проектными файлами. Имя агента и история сохраняются после перезагрузки.

Чтобы вернуться к работе, пользователь открывает рабочий проект/чат; для снятия специализированного профиля выбирает Gamma в Market. Существующее подтверждение замены и выбор проекта сохранены. Help не требует выбора рабочего проекта и не устанавливается как его market binding.

## Совместимость и развёртывание

Нативные агенты, навыки и безопасный инструмент реализованы для V1 и V2. Product UI и Market по-прежнему используют V1; эта работа не переносит project bindings и Help HTTP на отдельный V2 runner. Существующая зависимость Schema → Core/Protocol → Server сохранена. После изменения HttpApi выполнена генерация клиента через `bun run generate` в `packages/client`.

Новых системных зависимостей, платных сервисов и миграций базы нет. Нужны обычная сборка Gamma, доступная для записи data directory и существующая конфигурация LLM. Для Help используется выбранный штатный провайдер. Развёртывание должно включать встроенные markdown-ресурсы. Явный старый `default_agent: build` нужно убрать либо заменить на `gamma`, если администратор хочет новый стандарт и в своей конфигурации.

## Проверки

Проверки выполнялись из каталогов пакетов; существующее приложение не перезапускалось. Для браузера и настоящей модели использовался отдельный backend с временными data/workspace directories.

- V1: native agents, market permissions, защита plan/subagents, реальный HTTP/SQLite, подтверждения, смена и точные повторные запросы. Help endpoint требует авторизацию; открытие Help сохраняет рабочую привязку. Возврат к Gamma сохраняет историю и файл.
- V1 session runtime: реальные tools, SQLite, файлы и TaskTool с детерминированным LLM transport. Проверены исполнение Gamma по умолчанию, загрузка справки/каталога Guide, фактический отказ записи, сохранность специалиста и истории. Это runtime integration, но не проверка качества настоящей модели.
- Core V2: agents, market, permissions, skill plugin/tool и реальный `gamma_help`; запрещённые действия Guide остаются запрещёнными при расширяющей конфигурации.
- App: шесть тестов выбора агента. Playwright-сценарий на реальном backend проверяет нового Gamma, специалиста, Help, перезагрузку, неизменность рабочего профиля, возврат к Gamma и сохранение истории.
- `bun typecheck` прошёл в opencode, core и app. Все пять skills прошли quick_validate; аудит источников справки прошёл.
- Дополнительно проверена существующая интеграция презентаций: OOXML, редактирование, MCP и рендеринг. Для Chromium требуется указать существующий `PLAYWRIGHT_BROWSERS_PATH`: изолированный XDG тестов иначе не видит уже установленный браузер.

Итог: 54 теста V1, 24 теста Core, 6 тестов выбора агента в App, 10 регрессионных тестов презентаций и один браузерный сценарий прошли. Первый запуск презентационного набора обнаружил отсутствие Chromium в изолированном XDG; повтор с путём к установленному браузеру прошёл без изменения реализации.

Воспроизведение основных проверок из соответствующих каталогов:

```sh
# packages/opencode
bun test test/agent test/session/agent-market.test.ts test/server/agent-market.test.ts
bun typecheck
bun run script/gamma-guide-audit.ts

# packages/core
bun test test/agent.test.ts test/agent-market.test.ts test/permission.test.ts test/plugin/skill.test.ts test/tool-skill.test.ts
bun typecheck

# packages/app — E2E требует отдельный запущенный тестовый backend
bun test src/context/local-agent.test.ts
bun typecheck
GAMMA_SYSTEM_AGENTS_E2E=1 PLAYWRIGHT_SERVER_PORT=4181 PLAYWRIGHT_PORT=4485 bunx playwright test e2e/regression/system-agents.spec.ts --workers=1
```

### Проверка с настоящей LLM

На существующей пользовательской конфигурации `qwen/qwen3.5-plus` выполнены две обычные нативные сессии. Gamma создал `hello-gamma.txt` с содержимым `Gamma works` и проверил файл чтением. Guide реально вызвал встроенные skills и `gamma_help`, объяснил проекты/агентов, отказался читать `.env` и создавать приложение, помог сформулировать запрос исполнителю. Файл независимо проверен на диске. Новые платные API не настраивались.

Это проверка двух конкретных задач с настоящей моделью, а не гарантия качества любых ответов. Ограничения доступа дополнительно проверены независимо от поведения модели.

### Известные ограничения

Legacy production benchmark переключения вкладок не проходит уже на исходном состоянии: ожидаемые ссылки старого titlebar скрыты текущим интерфейсом. Повтор после изменений завершился теми же двумя ошибками; production build прошёл. Поэтому достоверное сравнение производительности этим тестом отсутствует; успешная сборка или функциональный E2E его не заменяют.

Guide намеренно не читает приватные runtime-логи, проектные файлы и секреты и не исправляет код. Продолжение Help сохраняет его ограниченную роль; разработка выполняется в обычном рабочем чате. Product Market остаётся V1-интеграцией. Актуальность встроенной документации требует описанного review при изменении продукта; живой каталог обновляется автоматически.
